# 任务 7.1.10 · 前端联调与质量门槛

> 本任务是整个前端阶段的收尾验收。目标是让“能运行”变成“能稳定验证、能定位问题”。

## 一、最低质量门槛

在 `frontend` 目录执行：

```bash
npm run build
```

该命令会先运行 `vue-tsc -b`，再执行 Vite 构建。前者检查 `.vue` 模板和 TypeScript，后者检查生产打包。两个都通过，才算前端基础交付。

## 二、按链路联调

### 1. 认证链路

- 登录成功，Network 中看到 `/api/auth/login` 返回成功。
- `zm-token` 和 `zm-user` 写入 localStorage。
- 访问受保护路由时自动带 Bearer token。
- token 失效时 Pinia 用户状态和 localStorage 同时清空。

### 2. 题库链路

- 分类接口返回后，页面能展示过滤项。
- 题目接口参数包含当前页和筛选项。
- 后端 `records` 为空时显示空状态。
- 详情接口返回答案后，抽屉能展示它。

### 3. 面试链路

- 创建会话后地址栏带 `sessionId`，刷新可以恢复。
- chat 响应头是 `text/event-stream` 时逐段显示。
- chat 同步失败返回 JSON 时，能显示业务错误。
- 结束面试后，报告生成中会轮询，生成完成后停止。

### 4. 用户数据链路

- 错题本和收藏夹只在登录状态下请求。
- 增删改操作的 HTTP 方法和路径与后端 Controller 完全一致。
- 操作失败后按钮 loading 能恢复。

## 三、浏览器排错顺序

遇到“页面没有数据”，按这个顺序排查：

1. Console：有没有 TypeScript 编译或运行时异常。
2. Network：请求是否发出，URL、方法、参数是否正确。
3. Request Headers：需要登录的请求是否有 Authorization。
4. Response：后端返回的是统一 JSON，还是 SSE，字段是否符合类型。
5. Vue 状态：接口成功后是否真的给了 `ref.value` 赋值。
6. Template 条件：是否被 `loading`、`v-if` 或错误分支遮住。

不要一上来就改 CSS。接口没发出、字段名错误和条件渲染问题，改样式解决不了。

## 四、前端测试建议

当前项目已经有后端 Service 单元测试，但前端还没有测试脚本。前端功能稳定后再引入 Vitest 和 Vue Test Utils，优先测试纯逻辑：

- 分页参数和筛选条件转换。
- `toRankUser` 等数据转换函数。
- SSE 帧解析：半帧、多帧、delta/done/error。
- 登录失效后 store 清理。
- 报告轮询在成功和卸载时停止。

不要一开始就测试整个浏览器页面和真实后端，那会让学习成本和失败定位成本同时上升。先把可纯函数化的逻辑抽出来，再测试组件交互。

## 五、接口变更时的同步清单

后端新增或修改接口时，前端按顺序同步：

```text
后端 Controller/VO
  → frontend/src/types
  → frontend/src/api
  → 页面状态和转换函数
  → template 展示
  → 联调自测
```

如果接口字段从 `questionId` 改成 `id`，不要只改 template；类型、转换函数、事件参数和 API 路径拼接都要搜索确认。推荐使用：

```bash
rg -n "questionId|FavoriteQuestion|WrongQuestion" frontend/src
```

## 六、最终验收清单

- `npm run build` 通过。
- 页面不再直接调用 axios 或 fetch（SSE API 文件除外）。
- 页面有 loading、空状态、失败重试或失败提示。
- 受保护页面有路由守卫和页面内登录兜底。
- timer、SSE reader、事件监听等异步资源有生命周期清理。
- 能从任意一个页面反向讲清楚“用户操作 → API → 状态 → template”的完整路径。

## 七、初学者课堂：编译错误、运行时错误和接口错误

这三类错误要分开处理：

### 1. 编译/类型错误

发生在 `npm run build` 或编辑器检查阶段，例如：

```text
Property 'records' does not exist on type ...
```

通常是类型、import、模板变量或组件 props 不匹配。先修这类错误，因为代码还没有可靠进入浏览器。

### 2. 运行时错误

浏览器 Console 中出现：

```text
Cannot read properties of null
```

常见原因是接口尚未返回时就访问 `stats.today`，或 `find()` 没找到对象却继续读属性。使用 `v-if`、可选链 `?.`、默认值和正确的 loading 状态处理。

### 3. 接口/业务错误

Network 能看到请求，但响应是 401、403、404 或业务 `code != 0`。这时要检查 URL、方法、token、参数、后端日志和权限，不要把它误判成 Vue 渲染问题。

## 八、使用 Network 面板逐项看请求

点击一个题目后，在 Network 中依次检查：

```text
Request URL       是否是 /api/questions/数字
Request Method    是否是 GET
Query String      分页和筛选参数是否正确
Request Headers   需要登录时是否有 Authorization
Status Code       HTTP 层是否成功
Response          JSON 字段是否与 types 一致
```

如果请求成功但页面没变，再回到页面代码检查：

```ts
const detail = await fetchQuestionDetail(id)
activeQuestion.value = detail
```

是否真的执行、是否被异常提前中断、template 是否使用了同一个变量。

## 九、最小可复现排错法

遇到问题时不要同时改五个文件。按下面的顺序缩小范围：

1. 在 API 函数调用前打印参数，确认页面传入正确。
2. 在 Network 确认请求真实发出。
3. 在 response 后打印返回数据，确认结构。
4. 在赋值后检查 `ref.value` 是否改变。
5. 最后检查 template 条件和子组件 props。

定位完成后删除临时 `console.log`，或者把有价值的信息改成统一日志方案。调试日志不是永久业务代码。

## 十、前端自动化测试的学习顺序

建议从不依赖浏览器和后端的纯逻辑开始：

```text
SSE 字符串解析函数
  → 参数转换函数
  → 状态映射函数
  → API mock 下的组件交互
  → 路由和登录守卫
```

例如先把 SSE 解析从 `chatInterviewStream` 中抽成纯函数，输入字符串，输出事件数组。纯函数没有网络、定时器和 DOM，测试会简单很多；等逻辑稳定后再测试组件如何响应这些事件。
