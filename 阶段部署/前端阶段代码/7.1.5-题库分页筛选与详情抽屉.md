# 任务 7.1.5 · 题库分页、筛选与详情抽屉

> 本任务是第一个完整的“页面接接口”练习。建议先只实现题库，再把同样的模式迁移到错题本和收藏夹。

## 一、本任务要实现什么

完成下面的用户流程：

```text
进入题库
  → 拉取分类
  → 拉取第一页题目
  → 点击分类，页码回到 1 并重新请求
  → 点击下一页，只重新请求题目
  → 点击题目，拉取详情并打开抽屉
```

接口：

```text
GET /api/categories/tree
GET /api/questions?pageNum=1&pageSize=12&categoryId=2
GET /api/questions/{id}
```

## 三、先画出页面状态

不要边写 template 边猜变量。先列状态：

```ts
const categories = ref<QuestionCategory[]>([])
const activeCategoryId = ref<number | null>(null)
const questions = ref<QuestionListItem[]>([])
const total = ref(0)
const pageNum = ref(1)
const pageSize = 12
const loading = ref(false)
const drawerVisible = ref(false)
const activeQuestion = ref<QuestionDetail | null>(null)
```

这些状态可以分为三组：筛选/分页状态、列表请求状态、详情抽屉状态。分组之后，发生问题时更容易判断是列表接口错了，还是详情接口错了。

## 四、分步实现

### Step 1：封装分页接口

```ts
export interface QuestionPageParams {
  pageNum: number
  pageSize: number
  categoryId?: number
  difficulty?: number
  keyword?: string
}

export function fetchQuestionPage(
  params: QuestionPageParams,
): Promise<PageResult<QuestionListItem>> {
  return get<PageResult<QuestionListItem>>('/questions', { params })
}
```

筛选值为空时传 `undefined`，不要把 `null`、空字符串和数字 0 混在一起。后端动态 SQL 通常按 `null` 判断是否启用筛选。

### Step 2：实现列表加载函数

```ts
async function loadQuestions() {
  loading.value = true
  try {
    const page = await fetchQuestionPage({
      pageNum: pageNum.value,
      pageSize,
      categoryId: activeCategoryId.value ?? undefined,
    })
    questions.value = page.records
    total.value = page.total
  } finally {
    loading.value = false
  }
}
```

`finally` 很重要：成功和失败都要结束 loading。当前项目的 `http.ts` 已经弹出错误消息，如果页面还需要显示错误详情，可以再增加 `errorMessage` 状态并在 `catch` 中赋值。

### Step 3：处理筛选和分页的请求时机

```ts
watch(activeCategoryId, () => {
  pageNum.value = 1
  loadQuestions()
})

watch(pageNum, loadQuestions)
```

切换分类会触发两件事：先回到第一页，再加载第一页。这里要留意：如果 `pageNum` 原来已经是 1，修改它不会触发第二个 watch，所以分类 watch 自己必须调用一次 `loadQuestions()`。

实际项目中也可以把筛选和页码合并成一个 watch，并使用 `{ deep: true }`，但学习阶段先用显式 watch，比较容易看懂请求来源。

### Step 4：处理分类树

后端返回的是树形结构，而题目过滤项需要叶子分类。先转换再渲染：

```ts
const tree = await fetchCategoryTree()
categories.value = tree
  .flatMap((top) => (top.children?.length ? top.children : [top]))
  .map((category) => ({ id: category.id, name: category.name }))
```

这是“后端数据结构”和“页面所需结构”不同的典型场景。不要在 template 中写复杂的树形判断，页面模板应该尽量只负责展示。

### Step 5：列表、空状态和分页

```vue
<div v-loading="loading">
  <el-empty
    v-if="!loading && questions.length === 0"
    description="这个分类下还没有题目"
  />

  <div v-else>
    <QuestionCard
      v-for="question in questions"
      :key="question.id"
      :question="question"
      @open="openDetail"
    />
  </div>

  <el-pagination
    v-if="total > pageSize"
    v-model:current-page="pageNum"
    :total="total"
    :page-size="pageSize"
  />
</div>
```

空状态判断必须带 `!loading`，否则请求尚未完成时 `questions` 还是空数组，页面会短暂显示“没有题目”。加载、空数据、正常数据是三个不同状态。

### Step 6：打开详情抽屉

```ts
async function openDetail(id: number) {
  activeQuestion.value = await fetchQuestionDetail(id)
  drawerVisible.value = true
}
```

更完整的生产写法可以先打开抽屉、显示详情 loading，再把数据填入：

```ts
drawerVisible.value = true
activeQuestion.value = null
detailLoading.value = true
try {
  activeQuestion.value = await fetchQuestionDetail(id)
} finally {
  detailLoading.value = false
}
```

这样用户点击后立刻看到反馈，不会误以为点击没有生效。

## 五、关键理解

- `pageNum` 是页面状态，`offset` 是后端/数据库状态，前端不要自己计算 offset。
- `total` 来自后端 COUNT，前端只负责把它交给分页组件。
- 列表页不需要答案，详情页再取答案，符合后端 VO 的职责边界。
- `key` 应使用稳定的 `question.id`，不要用数组下标。
- 接口失败后必须让 loading 结束；否则页面会永久处于遮罩状态。

## 六、自测清单

- 首次进入页面请求分类和第一页题目。
- 切换分类后页码回到 1，且请求参数中的 `categoryId` 正确。
- 翻页只改变 `pageNum`，请求没有重复传错误分类。
- 空结果不会在 loading 期间闪现。
- 点击卡片能请求详情并显示答案。
- 断开后端后，loading 能结束，页面不会永久卡住。


## 七、初学者课堂：先建立“请求状态机”

一个列表请求至少存在四种状态：

```text
idle       还没有请求
loading    请求正在进行
success    请求成功，可能有数据，也可能是空数组
error      请求失败
```

当前代码用 `loading`、`questions.length` 和异常提示组合表达这些状态。以后页面更复杂时，可以显式写成：

```ts
type LoadState = 'idle' | 'loading' | 'success' | 'error'
const loadState = ref<LoadState>('idle')
const errorMessage = ref('')
```

不要把“数组为空”直接等同于“请求失败”。请求成功但没有题目是正常业务结果，失败则是网络或后端异常，两者给用户的提示和重试行为不同。

## 八、分页参数的完整流转

当用户点击第二页时：

```text
el-pagination 修改 pageNum
  → v-model 写入 pageNum.value = 2
  → watch(pageNum, loadQuestions)
  → fetchQuestionPage({ pageNum: 2, pageSize: 12 })
  → Axios 序列化成 ?pageNum=2&pageSize=12
  → 后端计算 offset=(2-1)*12
  → 返回 records + total
  → questions.value 和 total.value 更新
  → template 重新渲染
```

前端只保存用户能理解的页码，后端负责数据库的 offset。这样两端的职责不会混在一起。

## 九、筛选条件和防抖

当前分类按钮点击一次请求一次，适合低频操作。关键字搜索如果绑定 `input` 后每敲一个字就请求，会产生大量请求：

```text
线 → 线程 → 线程池 → 线程池的 → ...
```

入门实现建议用“输入框 + 搜索按钮/Enter”提交；后续再学习 debounce，把连续输入合并成一次请求。不要一开始就引入复杂库，先把请求触发时机想明白。

## 十、竞态问题：快速切换分类

假设请求 A 查询 Java，请求 B 查询 Redis。B 先返回，页面显示 Redis；A 后返回，旧结果可能把页面覆盖成 Java。这叫请求竞态。

当前简单页面可以先通过 loading 和低频操作降低概率；更稳的做法是给每次请求一个序号：

```ts
let requestId = 0

async function loadQuestions() {
  const currentId = ++requestId
  const page = await fetchQuestionPage(params)
  if (currentId !== requestId) return
  questions.value = page.records
}
```

或者使用 `AbortController` 取消上一次 fetch。理解这个问题后，你会发现“接口返回了但页面显示旧数据”通常不是 Vue 没更新，而是旧请求晚到覆盖了新请求。

## 十一、详情抽屉的两种加载策略

策略 A：请求完成后再打开抽屉，代码简单，但用户点击后可能短暂没有反馈。

策略 B：先打开抽屉，再显示 detail loading，完成后填充数据，体验更好：

```ts
drawerVisible.value = true
activeQuestion.value = null
detailLoading.value = true
try {
  activeQuestion.value = await fetchQuestionDetail(id)
} catch {
  // 抽屉内显示重试
} finally {
  detailLoading.value = false
}
```

选择不是绝对的。学习重点是：用户点击和网络结果之间有时间差，这段时间必须有明确状态。
