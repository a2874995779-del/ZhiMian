# 任务 7.1.6 · 仪表盘与排行榜接口驱动页面

> 本任务练习“接口返回数据不等于页面直接照搬数据”：页面需要计算展示值、转换状态，并提供失败重试。

## 一、本任务涉及的文件

| 文件 | 作用 |
|---|---|
| `api/dashboard.ts` | 获取仪表盘统计 |
| `types/dashboard.ts` | 仪表盘数据契约 |
| `views/Dashboard.vue` | 加载、计算、错误状态 |

## 二、仪表盘分步实现

### Step 1：定义页面状态

```ts
const stats = ref<DashboardStats | null>(null)
const loading = ref(false)
const errorMessage = ref('')
```

`null` 代表“还没有成功拿到数据”，不是“数据全是 0”。这让模板可以区分首次加载、请求失败和真实的空统计。

### Step 2：请求函数中清理旧错误

```ts
async function loadDashboard() {
  loading.value = true
  errorMessage.value = ''
  try {
    stats.value = await fetchDashboard()
  } catch (err) {
    errorMessage.value = err instanceof Error
      ? err.message
      : '仪表盘加载失败'
  } finally {
    loading.value = false
  }
}
```

重新加载前清空错误，否则即使第二次请求成功，旧错误文字也可能继续显示。错误类型在 TypeScript 中是 `unknown` 思维，不要默认强转成某个对象。

### Step 3：用 computed 计算进度

```ts
const progressPercent = computed(() => {
  if (!stats.value || stats.value.today.goal <= 0) return 0
  return Math.min(
    100,
    Math.round((stats.value.today.done / stats.value.today.goal) * 100),
  )
})
```

派生数据用 `computed`，不要在每个 template 表达式里重复计算。这里还处理了目标为 0 和超过 100% 两个边界。

### Step 4：模板按状态分支

```vue
<div v-loading="loading">
  <el-result v-if="!loading && errorMessage" :title="errorMessage">
    <template #extra>
      <el-button type="primary" @click="loadDashboard">
        重新加载
      </el-button>
    </template>
  </el-result>

  <el-empty v-else-if="!loading && !stats" description="暂无统计" />

  <div v-else-if="stats">
    <ProgressRing :value="progressPercent" />
    <TrendChart :points="stats.trend" />
  </div>
</div>
```

先处理错误，再处理空数据，最后展示正常数据。正常分支用 `v-else-if="stats"`，TypeScript 和读代码的人都能看出这里数据已经存在。

## 三、排行榜分步实现

### Step 1：用有限类型表示榜单类型

```ts
export type RankType = 'total' | 'daily'

const rankType = ref<RankType>('total')
const rankUsers = ref<RankUser[]>([])
```

切换函数只接受合法值：

```ts
function changeRankType(type: RankType) {
  if (rankType.value === type) return
  rankType.value = type
  loadRanks()
}
```

### Step 2：接口数据转换为页面数据

后端记录和颁奖台组件需要的字段可能不同，显式转换：

```ts
function toRankUser(record: RankRecord): RankUser {
  return {
    rank: record.rank,
    userId: record.userId,
    nickname: record.nickname,
    count: record.count,
    badges: badgesFor(record),
    avatarHue: avatarHue(record.userId),
  }
}
```

转换函数是一个很好的边界：后端字段变化时优先改这里，`PodiumCard` 不需要知道后端细节。

### Step 3：拆分榜单展示区域

```ts
const podium = computed(() => rankUsers.value.slice(0, 3))
const restRows = computed(() => rankUsers.value.slice(3))
```

`slice` 不会修改原数组，适合 computed。前三名和其他名次是不同视觉组件时，先在页面层拆出两个数据集合。

## 四、子组件的 props 设计

子组件只接受展示所需的最小数据：

```ts
const props = defineProps<{
  user: RankUser
}>()
```

不要把整个 `DashboardStats` 或 `RankRecord` 传进只需要昵称和分数的组件。props 越小，组件越容易复用和测试。

## 五、自测清单

- 后端正常时仪表盘显示真实的进度、趋势和统计。
- 仪表盘请求失败时能看到错误和“重新加载”。
- 目标题数为 0 时不会出现除零或 `NaN`。
- 总榜和日榜切换时 URL 参数分别是 `type=total`、`type=daily`。
- 排行榜空数据时不会访问 `rankUsers[0]` 造成运行时错误。
- 能说明哪些值应该是 `ref`，哪些值应该是 `computed`。

## 六、初学者课堂：服务器数据和页面派生数据

后端返回的是事实数据，例如：

```ts
stats.today.done = 3
stats.today.goal = 10
```

页面需要的是派生数据：进度百分比 30%。这个百分比不是服务器事实，适合用 `computed`：

```ts
const progressPercent = computed(() => {
  if (!stats.value) return 0
  return Math.round((stats.value.today.done / stats.value.today.goal) * 100)
})
```

如果把 `progressPercent` 也用一个 ref 保存，就会出现两个状态需要同步：统计更新了，百分比可能忘记更新。能由已有状态推导出的值，优先不要重复存储。

## 七、`computed` 和函数的选择

```ts
const podium = computed(() => rankUsers.value.slice(0, 3))
```

模板每次渲染都会读取 `podium`，Vue 会根据依赖缓存计算结果。适合稳定的派生状态。

```ts
function avatarHue(userId: number) {
  return userId % 6
}
```

函数适合带参数的转换或动作。不要把昂贵的无参数计算写成 template 中直接调用的函数，页面频繁更新时它可能被反复执行。

## 八、`v-if` 和请求状态的顺序

仪表盘推荐按这个逻辑写：

```text
loading       显示加载反馈
error         显示错误和重试
stats=null    显示空状态/登录提示
stats 有值    显示正常内容
```

不要只写 `v-if="!stats"` 就显示“暂无数据”，因为请求刚开始时 `stats` 也是 null。用户会看到“暂无数据”一闪而过，这不是数据真的为空，而是状态表达不准确。

## 九、排行榜切换的请求竞态

总榜和日榜切换时也可能出现旧请求覆盖新请求。当前 `loadRanks` 应该至少在开始时记录当前 `rankType`，返回后确认仍然是同一种榜单；更稳的版本可以复用 7.1.5 中的请求序号或 AbortController。

这是一个很值得记住的前端问题：后端按顺序处理请求，并不代表浏览器按顺序收到响应。

## 十、组件 props 的设计练习

尝试把 `ProgressRing` 改成只接受：

```ts
defineProps<{
  value: number
  label?: string
  size?: number
}>()
```

它不应该知道 `DashboardStats` 的完整结构，也不应该自己调用 `/dashboard`。这样它可以被其他页面复用，也可以在没有后端的情况下单独测试。
