## 三、浏览器和后端的关系

浏览器不会直接调用 Java 方法。它只会发送 HTTP 请求：

```text
浏览器
  -- GET /api/questions?pageNum=1 --> Spring Boot Controller
  <-- HTTP 状态码 + JSON 响应       --
```

后端的 Controller 负责接收请求和返回 JSON；前端的 API 文件负责发请求和读取 JSON。Vue 只是负责把读到的数据显示出来，它不替代 HTTP，也不替代后端权限。

一个请求至少包含：

```text
方法       GET / POST / PUT / DELETE
URL        /api/questions
参数       query、path variable、request body
请求头     Authorization、Content-Type
响应       HTTP status + response body
```

例如登录：

```http
POST /api/auth/login
Content-Type: application/json

{"username":"user01","password":"123456"}
```

响应体是 JSON 文本，Axios 会把它解析成 JavaScript 对象，再交给你的 TypeScript 代码。

## 四、URL 参数的三种位置

### 1. Query 参数

```text
GET /api/questions?pageNum=1&pageSize=10&difficulty=2
```

适合分页、筛选、排序。Axios 中通常写在 `config.params`：

```ts
get('/questions', {
  params: { pageNum: 1, pageSize: 10, difficulty: 2 },
})
```

### 2. Path 参数

```text
GET /api/questions/7
```

适合表示一个明确资源。前端用模板字符串把 id 放进路径：

```ts
get(`/questions/${id}`)
```

### 3. Body 参数

```text
POST /api/auth/login
Body: { username, password }
```

适合提交对象或较长内容。不要把密码拼在 URL 中，URL 可能出现在历史记录、代理日志和监控中。

## 五、JavaScript 模块

`frontend/src/api/auth.ts` 导出登录函数：

```ts
export function login(username: string, password: string) {
  return post<LoginResult>('/auth/login', { username, password })
}
```

store 再导入它：

```ts
import { login as loginApi } from '../api/auth'
```

`export` 是“允许别的模块使用”，`import` 是“在当前模块引入”。每个文件都有自己的作用域，import 关系就是依赖关系。不要为了省事把所有函数挂到全局对象上，那会让依赖来源和命名冲突变得不可控。

`as loginApi` 是导入时改本地名字，避免和 store 里的 `login` 函数重名。它不改变导出的函数，只改变当前文件中的引用名。

## 六、对象、解构和可选链

接口返回：

```ts
const result = {
  token: 'abc',
  user: { nickname: '小明' },
}
```

读取可以写：

```ts
result.user.nickname
```

如果 `user` 可能为空：

```ts
result.user?.nickname ?? '未登录'
```

`?.` 表示左侧为空时不要继续访问；`??` 表示左侧是 null/undefined 时使用默认值。它们能减少“页面数据还没回来就访问属性”的运行时错误，但不能替代正确的类型和状态设计。

## 七、Promise 和异步执行

普通函数执行完马上返回结果：

```ts
function add(a: number, b: number) {
  return a + b
}
```

网络请求需要等待，所以返回 Promise：

```ts
function loadQuestion(id: number): Promise<QuestionDetail> {
  return fetchQuestionDetail(id)
}
```

调用时：

```ts
async function openDetail(id: number) {
  try {
    const detail = await loadQuestion(id)
    console.log(detail.title)
  } catch (error) {
    console.error(error)
  }
}
```

`await` 只暂停当前 `async` 函数，不会阻塞浏览器的所有事件。用户仍然可以看到 loading、点击其他按钮，除非你在页面状态中主动禁用了它们。

## 八、JSON、对象和 TypeScript 类型

JSON 是可以通过 HTTP 传输的文本格式：

```json
{"id":7,"title":"Redis 为什么快？"}
```

解析后是 JavaScript 对象：

```ts
{ id: 7, title: 'Redis 为什么快？' }
```

TypeScript interface 只是编译期描述：

```ts
interface Question {
  id: number
  title: string
}
```

interface 不会被发送到后端，也不会在浏览器自动验证 JSON。它的用途是让编译器、编辑器和你自己对字段形成共同约定。

## 九、Vite 代理为什么重要

前端开发服务器通常在 `localhost:5173`，后端在 `localhost:8080`，这是两个源。当前配置让浏览器请求 `/api/...`，Vite 在开发时把它转发给后端。这样页面代码不用硬编码后端地址，也减少跨域配置问题。

```text
浏览器 → localhost:5173/api/questions
Vite   → localhost:8080/api/questions
```

生产部署时，代理可能由 Nginx 或网关完成，前端仍然使用相对路径 `/api`，迁移更方便。
