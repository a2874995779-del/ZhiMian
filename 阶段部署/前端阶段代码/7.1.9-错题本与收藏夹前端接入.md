# 任务 7.1.9 · 错题本与收藏夹前端接入

> 后端设计见 `阶段代码/6.4.1-错题本功能设计与实现指南.md` 和 `6.4.2-收藏夹功能设计与实现指南.md`。本任务只写前端接入方法，数据库、Mapper、Service 和 Controller 按后端文档完成后再开始。

## 一、本任务要实现什么

错题本和收藏夹都属于登录用户数据，页面需要完成：

```text
登录校验
  → 分页查询
  → 筛选/换页
  → 操作单条记录
  → 操作成功后刷新或局部更新
```

推荐路由：

```text
/wrong-questions   错题本
/favorites         收藏夹
```

两者的产品语义不同：错题本是答题行为自动沉淀，收藏夹是用户主动标记。前端不要把它们合并成一个“题目状态”字段。

## 二、错题本前端步骤

### Step 1：定义类型

根据后端实际 VO 字段建立：

```ts
export interface WrongQuestionQuery {
  pageNum: number
  pageSize: number
  status?: number
  categoryId?: number
  keyword?: string
}

export interface WrongQuestionItem {
  questionId: number
  title: string
  wrongCount: number
  correctCount: number
  status: number
  lastWrongTime: string
  lastReviewTime?: string | null
}
```

如果后端 VO 叫 `id` 而不是 `questionId`，以真实接口为准。类型是契约，不要为了配合模板擅自改名。

### Step 2：封装 API

```ts
export function fetchWrongQuestions(
  params: WrongQuestionQuery,
): Promise<PageResult<WrongQuestionItem>> {
  return get<PageResult<WrongQuestionItem>>('/wrong-questions', { params })
}

export function markWrongQuestionMastered(questionId: number) {
  return put<void>(`/wrong-questions/${questionId}/mastered`)
}

export function markWrongQuestionUnmastered(questionId: number) {
  return put<void>(`/wrong-questions/${questionId}/unmastered`)
}

export function removeWrongQuestion(questionId: number) {
  return del<void>(`/wrong-questions/${questionId}`)
}
```

HTTP 方法、路径和参数要逐项对照后端 Controller。特别注意 `PUT` 和 `DELETE` 不能因为“看起来都是操作”就全部写成 `post`。

### Step 3：组织页面状态

```ts
const rows = ref<WrongQuestionItem[]>([])
const total = ref(0)
const pageNum = ref(1)
const pageSize = 10
const status = ref<number | undefined>(undefined)
const keyword = ref('')
const loading = ref(false)
```

筛选按钮改变时：

```ts
function changeStatus(next: number | undefined) {
  status.value = next
  pageNum.value = 1
  loadPage()
}
```

输入框建议使用 `draftKeyword` 和 `keyword` 分开：输入过程中不请求，点击搜索或按 Enter 后才提交查询条件。

### Step 4：完成操作后的数据策略

初版建议操作成功后重新拉当前页：

```ts
async function markMastered(row: WrongQuestionItem) {
  await markWrongQuestionMastered(row.questionId)
  await loadPage()
}
```

重新请求简单可靠，能处理后端排序、总数和状态筛选变化。等功能稳定后再考虑局部更新或乐观更新。

## 三、收藏夹前端步骤

### Step 1：定义类型和 API

```ts
export interface FavoriteQuery {
  pageNum: number
  pageSize: number
  categoryId?: number
  difficulty?: number
  keyword?: string
}

export interface FavoriteQuestionItem {
  questionId: number
  title: string
  categoryName: string
  difficulty: number
  createTime: string
}

export function fetchFavorites(
  params: FavoriteQuery,
): Promise<PageResult<FavoriteQuestionItem>> {
  return get<PageResult<FavoriteQuestionItem>>('/favorites', { params })
}

export function addFavorite(questionId: number) {
  return post<void>(`/favorites/questions/${questionId}`)
}

export function removeFavorite(questionId: number) {
  return del<void>(`/favorites/questions/${questionId}`)
}

export function checkFavorite(questionId: number): Promise<boolean> {
  return get<boolean>(`/favorites/questions/${questionId}`)
}
```

### Step 2：收藏按钮状态

题目详情抽屉需要一个 `favorited` 状态：

```ts
const favorited = ref(false)
const favoriteLoading = ref(false)

async function loadFavoriteState(id: number) {
  if (!auth.token) return
  favorited.value = await checkFavorite(id)
}
```

收藏/取消收藏成功后再改 `favorited`，或重新查询一次。初版优先保证状态与后端一致，不要只改图标却不处理请求失败回滚。

## 四、路由和权限

```ts
{
  path: '/wrong-questions',
  name: 'wrong-questions',
  component: () => import('../views/WrongBook.vue'),
  meta: { label: '错题本', icon: 'collection', requiresAuth: true },
}
```

收藏夹同理。页面还要保留未登录兜底，因为用户可能在页面停留期间退出登录，不能只依赖首次路由守卫。

## 五、自测清单

- 未登录访问错题本/收藏夹会被守卫拦截。
- 登录后能正确加载第一页，退出后页面不再继续请求。
- 换筛选条件时页码回到 1。
- 错题标记掌握、取消掌握、删除后列表状态正确。
- 收藏、取消收藏后图标和收藏夹列表一致。
- 后端请求失败时不会把按钮永久锁死。
- 页面关闭或切换路由后没有遗留请求定时器。

## 六、初学者课堂：为什么要先完成后端再接前端

前端页面依赖三个后端事实：URL、HTTP 方法、响应字段。只要其中一个没有确定，前端就只能猜：

```text
后端 Controller 定义路径和方法
后端 VO 定义字段
前端 types 翻译字段
前端 api 封装调用
页面消费 api 返回值
```

所以这两个功能的推荐顺序是：先按后端阶段文档完成并用接口工具验证，再开始前端类型。不要先凭想象写 `FavoriteItem`，否则后端字段一改，你会同时改类型、页面和假数据。

## 七、错题本页面的完整数据流

以点击“标记掌握”为例：

```text
用户点击按钮
  → 页面拿到 row.questionId
  → markWrongQuestionMastered(questionId)
  → http.ts 自动带 token，发送 PUT
  → 后端校验当前用户并更新 status
  → API Promise 成功
  → 页面重新请求当前分页
  → rows.value 和 total.value 更新
  → template 重新渲染
```

其中“当前用户是谁”不能由前端传一个 userId 决定，必须由后端从 JWT/UserContext 获取。前端只传题目 id；这是安全边界，也是你在面试中应该主动说明的点。

## 八、为什么初版建议操作成功后重新加载

你可能会想直接写：

```ts
row.status = 1
```

这叫局部更新，速度快，但它可能漏掉：

- 当前筛选条件下这条记录应该消失；
- 总数发生变化；
- 后端更新时间被修改；
- 后端排序发生变化；
- 操作实际影响了其他统计字段。

初版用“操作成功 → `await loadPage()`”更容易保证页面和数据库一致。等接口链路稳定，再用局部更新优化体验，并明确哪些字段需要同步。

## 九、收藏按钮的三种状态

收藏按钮至少要考虑：

```text
未登录       不请求检查接口，点击时引导登录
已登录未收藏 显示“收藏”，点击后 loading
已登录已收藏 显示“取消收藏”，点击后 loading
```

不要只用 `favorited: boolean`，还要有 `favoriteLoading`，否则用户快速点击可能连续发出添加/删除请求，造成竞态。

## 十、列表页和详情页的状态同步

用户在详情抽屉中取消收藏后，收藏夹列表不会自动知道这个变化。初版可以在关闭抽屉或返回收藏夹时重新加载；进阶可以使用 Pinia 保存收藏 id 集合，让题库详情、题库列表和收藏夹共享状态。

但不要为了一个布尔值立刻引入全局 store。先用页面局部状态完成闭环，遇到跨页面同步需求时再提升状态层级。

## 十一、后端字段不确定时的排查方法

1. 打开后端 `WrongQuestionVO` 或 `FavoriteQuestionVO`。
2. 查看 Controller 的返回类型。
3. 用 Postman/curl 调用真实接口。
4. 打开浏览器 Network 查看实际 JSON。
5. 最后再写 TypeScript 类型。

以 Network 看到的 JSON 为准，不要以数据库列名或自己的猜测为准。
