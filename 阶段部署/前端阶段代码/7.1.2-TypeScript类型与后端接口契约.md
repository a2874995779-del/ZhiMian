# 任务 7.1.2 · TypeScript 类型与后端接口契约

> 本任务只关注“数据长什么样”。先把后端 VO/DTO 翻译成 TypeScript，再写请求函数和页面。

## 一、本任务要实现什么

建立这条规则：

```text
后端响应字段
    ↓ 一一映射
frontend/src/types/*.ts
    ↓ 被 api 函数引用
页面拿到有类型的数据
```

类型不是装饰品。它会在接口字段改名、分页对象写错、SSE 事件漏处理时尽早提醒你。

## 二、当前项目的类型分层

| 文件 | 当前职责 |
|---|---|
| `types/user.ts` | 用户和登录结果 |
| `types/question.ts` | 题目列表、题目详情、分类 |
| `types/interview.ts` | 面试方向、会话、消息、报告、SSE 事件 |
| `types/dashboard.ts` | 仪表盘统计 |
| `types/rank.ts` | 排行榜记录 |
| `api/question.ts` | 题目接口专用分页参数和分页返回类型 |

## 三、分步实现

### Step 1：从后端 VO 提取前端展示类型

题目列表后端不返回答案，所以列表类型不应把 `answer` 当必填字段：

```ts
export interface QuestionListItem {
  id: number
  title: string
  categoryId: number
  categoryName: string
  tags: string[]
  difficulty: number
  viewCount: number
}

export interface QuestionDetail extends QuestionListItem {
  content: string | null
  answer: string
}
```

列表和详情不是同一份数据。把详情的大字段直接塞进列表类型，会让页面误以为所有列表项都有答案，也会掩盖后端实际没有返回该字段的问题。

### Step 2：使用联合类型表达有限状态

面试方向不是任意字符串：

```ts
export type InterviewDirectionCode =
  | 'java_concurrency'
  | 'jvm'
  | 'mysql'
  | 'redis'
  | 'system_design'
```

这样调用：

```ts
createInterview('jvm')
```

是安全的；调用 `createInterview('python')` 会在编译期暴露问题。后端状态同样可以写成 `0 | 1 | 2`，再用 `STATUS_META` 把状态码映射成页面文案和色调。

### Step 3：理解泛型分页

分页结构本身固定，记录类型会变化：

```ts
export interface PageResult<T> {
  records: T[]
  total: number
  pageNum: number
  pageSize: number
}
```

因此：

```ts
Promise<PageResult<QuestionListItem>>
Promise<PageResult<InterviewSessionListVO>>
```

复用的是分页外壳，不是把题目和面试记录混成一种类型。`T` 可以理解为“这一页每条记录的类型占位符”。

### Step 4：区分必填字段和可选字段

后端暂时没有提供题目代码示例时：

```ts
codeSnippet?: {
  language: string
  code: string
}
```

页面必须防守式使用：

```vue
<MockCodeBlock
  v-if="question.codeSnippet"
  :language="question.codeSnippet.language"
  :code="question.codeSnippet.code"
/>
```

`?` 表示字段可能不存在，不代表一定是 `null`。如果后端明确返回 `null`，要写 `string | null`，两者不要混用。

### Step 5：给新功能建立类型

在实现错题本、收藏夹时，先阅读对应后端阶段文档，再新建 `types/wrong-question.ts` 和 `types/favorite.ts`。字段命名以接口真实返回为准，不要先写页面再靠 `any` 猜字段。

推荐保留三类类型：

```ts
export interface WrongQuestionQuery {
  pageNum: number
  pageSize: number
  status?: number
  categoryId?: number
  keyword?: string
}

export interface WrongQuestionItem {
  questionId: number
  title: string
  wrongCount: number
  correctCount: number
  status: number
  lastWrongTime: string
}

export interface FavoriteQuestionItem {
  questionId: number
  title: string
  categoryName: string
  difficulty: number
  createTime: string
}
```

查询参数、列表项和详情/操作返回值不一定相同，按用途拆开会比一个“万能接口”更清楚。

## 四、常见错误

- 把后端 `Long` 当成 TypeScript `bigint`：JSON 接口中的普通 id 通常按 `number` 使用，除非项目专门处理超大整数。
- 把所有字段写成 `any`：这会让类型检查失去意义。
- 把后端数字状态直接在 template 中写一堆 `status === 1`：集中放在映射对象或函数中。
- 把 `records` 写成 `object[]`：调用方就失去字段提示。
- 页面收到接口数据后又手写一份不同结构的对象：需要转换时明确写 `toRankUser` 这类转换函数。

## 六、初学者课堂：类型到底解决了什么问题

假设后端返回：

```json
{
  "id": 1,
  "title": "线程池的核心参数有哪些？",
  "difficulty": 2
}
```

如果你把结果声明成 `any`：

```ts
const question: any = await fetchQuestionDetail(1)
question.titel
```

`titel` 拼错了，编辑器不会提示，浏览器运行时才得到 `undefined`。如果使用：

```ts
const question: QuestionDetail = await fetchQuestionDetail(1)
question.titel
```

TypeScript 会在构建阶段提醒你字段不存在。它不能保证后端永远返回正确数据，但可以保证你写前端代码时遵守自己声明的契约。

## 七、类型、运行时数据和接口校验不是一回事

TypeScript 类型会在编译后消失。下面的代码不会在运行时自动检查后端：

```ts
const page = await fetchQuestionPage(params)
```

如果后端把 `total` 错误返回成字符串，TypeScript 不会在浏览器运行时替你拦截。学习阶段先依靠后端接口约定和 Network 检查；项目变复杂后，可以引入 Zod 等运行时校验库，把“外部数据进入前端的边界”再验证一次。

## 八、逐步理解泛型

先看没有泛型的写法：

```ts
interface QuestionPage {
  records: QuestionListItem[]
  total: number
}
```

它只能描述题目分页。面试历史还要复制一份几乎一样的接口。泛型把“每条记录是什么”抽出来：

```ts
interface PageResult<T> {
  records: T[]
  total: number
  pageNum: number
  pageSize: number
}
```

当写 `PageResult<QuestionListItem>` 时，编译器把 `T` 替换成 `QuestionListItem`；写 `PageResult<InterviewSessionListVO>` 时，替换成面试记录。泛型不是运行时容器，它只是让同一个结构在编译期适配多种数据。

## 九、接口类型的三层思路

推荐按以下顺序建模：

```text
请求参数类型     用户/页面发给后端什么
响应数据类型     后端成功后返回什么
页面展示类型     页面为了显示是否需要转换
```

例如排行榜后端返回 `RankRecord`，颁奖台需要额外的 `badges` 和 `avatarHue`，就用 `toRankUser` 转换，而不是修改后端类型假装这些字段来自接口。转换函数也让你更容易写单元测试。

## 十、`null`、`undefined` 和空字符串

这三个值在筛选表单里含义不同：

```ts
undefined // 通常表示这个参数不传
null      // 明确表示没有值，JSON 中会出现 null
''        // 用户传了空文本
```

题库请求中使用：

```ts
categoryId: activeCategoryId.value ?? undefined
```

表示没有选分类时不传 `categoryId`。不要把数字 id 写成 `0` 代表“全部”，除非后端明确规定 0 是合法语义。
