# 任务 7.1.1 · Vue 3 工程基础与应用入口

> 请亲手把关键代码敲进 `frontend`，完成后运行 `npm run build`。
> 本任务目标不是做页面，而是先建立“一个 Vue 页面是怎样被启动、挂载和组织起来的”这张地图。

## 一、本任务要实现什么

你需要能够解释下面这条启动链路：

```text
index.html 的 #app
        ↓
src/main.ts 创建 Vue 应用、注册 Pinia/Element Plus/Router
        ↓
src/App.vue 渲染 AppShell
        ↓
AppShell 渲染 RouterView
        ↓
router 根据 URL 懒加载某个 views 页面
```

## 三、分步实现

### Step 1：读懂单文件组件

Vue 的 `.vue` 文件通常由三块组成：

```vue
<script setup lang="ts">
import { ref } from 'vue'

const count = ref(0)
</script>

<template>
  <button type="button" @click="count++">{{ count }}</button>
</template>

<style scoped>
/* 本阶段不要求你设计样式 */
</style>
```

`<script setup>` 中声明的变量可以直接在 template 使用。`ref(0)` 返回的是一个响应式引用：在 JavaScript 中修改要写 `count.value`，在 template 中 Vue 会自动解包，所以写 `count`。

### Step 2：理解 `main.ts`

当前入口大致是：

```ts
const app = createApp(App)

app.use(createPinia())
app.use(ElementPlus)
app.use(router)
app.mount('#app')
```

插件注册顺序不是背诵题。关键是：`App.vue` 以及它的后代组件渲染前，Pinia、Element Plus 和 Router 已经被挂到应用实例上。没有 `app.use(router)`，`useRouter()` 和 `<RouterView>` 都不能正常工作；没有 `app.use(createPinia())`，`useAuthStore()` 会报 Pinia 未安装。

### Step 3：新建练习页面

新建 `src/views/PracticeSandbox.vue`，完成三个状态：

```ts
const keyword = ref('')
const submittedKeyword = ref('')
const submitted = ref(false)

function submit() {
  submittedKeyword.value = keyword.value.trim()
  submitted.value = true
}
```

模板中做一个输入框、提交按钮和条件展示。这里练习的是“输入状态”和“提交后的展示状态”分开：用户正在输入的内容不等于已经提交的查询条件。

把页面临时加到路由：

```ts
{
  path: '/practice-sandbox',
  name: 'practice-sandbox',
  component: () => import('../views/PracticeSandbox.vue'),
}
```

### Step 4：理解懒加载

路由里的：

```ts
component: () => import('../views/QuestionBank.vue')
```

不是立即执行 `QuestionBank.vue`，而是用户第一次进入该路由时再加载页面代码。页面较多时，这能减少首屏 JavaScript 体积。它和后端 Controller 的“按 URL 找处理器”有点相似，但这里加载的是前端组件模块。

### Step 5：理解响应式边界

下面三种写法要区分：

```ts
const count = ref(0)                 // 一个值
const form = reactive({ keyword: '' }) // 一个对象
const rows = ref<Question[]>([])     // 一个数组引用
```

学习期优先使用 `ref`，因为 `.value` 会明确提醒你正在修改响应式引用。接口返回后通常写：

```ts
rows.value = page.records
```

不要把 API 返回值直接赋给一个普通 `let rows = []`，那样 Vue 不会知道页面需要更新。

## 四、关键理解

- `App.vue` 不负责所有页面业务，它只负责应用根结构。
- `AppShell` 是布局组件，`RouterView` 是当前路由页面的插槽。
- 页面组件负责一个页面的状态和流程；可复用的卡片、抽屉、图表应该拆到 `components`。
- `ref` 的核心价值是让“状态变化 → 视图更新”自动发生。
- `scoped` 只影响 CSS 作用域，不会影响 script 和 template 的变量访问。

## 六、初学者课堂：浏览器到底做了什么

当你在地址栏输入 `http://localhost:5173/questions`，浏览器首先向 Vite 开发服务器请求页面资源。Vite 返回 `index.html` 和 JavaScript 模块，JavaScript 执行 `main.ts`，Vue 创建应用并把内容挂载到：

```html
<div id="app"></div>
```

“挂载”可以先理解成：Vue 找到这个空容器，把 `App.vue` 的模板转换成浏览器能显示的 DOM，并且建立“状态变化后重新更新 DOM”的关系。

后续你点击题库页面的按钮，并不是浏览器重新请求一个完整 HTML 页面，而是 Vue 修改当前页面的状态，局部更新 DOM。这就是单页应用（SPA）和传统多页跳转最直观的区别。

## 七、逐步练习：从静态文字到响应式页面

### Step 1：先写静态模板

```vue
<template>
  <section>
    <h1>练习页面</h1>
    <p>这里是 Vue 页面</p>
  </section>
</template>
```

这一步只验证路由和组件加载，不要一开始就接接口。

### Step 2：加入一个 ref

```ts
const count = ref(0)

function increase() {
  count.value += 1
}
```

```vue
<button type="button" @click="increase">
  点击次数：{{ count }}
</button>
```

执行过程是：用户点击 → `increase` 执行 → `count.value` 变化 → Vue 发现依赖它的模板发生变化 → 按钮文字更新。你没有手动调用 `document.querySelector`，因为 Vue 帮你维护了状态和 DOM 的对应关系。

### Step 3：加入条件和循环

```ts
const visible = ref(true)
const topics = ref(['线程池', 'Redis', 'MySQL'])
```

```vue
<button type="button" @click="visible = !visible">切换</button>
<p v-if="visible">当前可见</p>
<ul>
  <li v-for="topic in topics" :key="topic">{{ topic }}</li>
</ul>
```

在 `<script setup>` 中，`ref` 在 JavaScript 里严格来说需要 `.value`，但模板会自动解包，所以 `visible = !visible` 这种写法在模板事件表达式里可以工作。为了初学时少混淆，复杂逻辑仍建议写在 script 函数中。

## 八、必须理解的三个 Vue 语法

### 1. `{{ }}`：读取数据

```vue
<span>{{ question.title }}</span>
```

它用于文本插值。不要把用户输入用 `v-html` 直接渲染，除非你明确做过 HTML 清洗；普通文本使用双大括号会进行安全转义。

### 2. `:`：绑定 JavaScript 值

```vue
<QuestionCard :question="question" />
<el-pagination :total="total" />
```

没有冒号时，`total="total"` 是字符串文字；有冒号时，Vue 才会读取变量 `total`。

### 3. `@`：监听事件

```vue
<button @click="loadQuestions">刷新</button>
```

`@click` 是 `v-on:click` 的缩写。事件处理函数可以是简单表达式，也可以是 script 中的函数。请求、校验和多步逻辑应该放在函数里，模板不要写成一大串业务表达式。

## 九、常见报错排查

### `Cannot find module`

通常是 import 路径写错、文件大小写不一致或文件还没有创建。Windows 对大小写不敏感，但构建部署环境可能敏感，所以路径和文件名要完全一致。

### `Property xxx does not exist`

模板里使用了 script 没有声明的变量，或者变量名称写错。先在 `.vue` 文件中搜索这个名字，再检查拼写和作用域。

### 页面一片空白

先看 Console 第一条错误。Vue 模板中的一个运行时异常就可能让页面无法正常渲染，不要先怀疑 CSS。
