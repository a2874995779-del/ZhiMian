# 任务 7.1.8 · 面试历史、报告生成与轮询

> 本任务练习三个真实前端问题：分页列表、详情抽屉中的二次请求、异步任务状态轮询。

## 一、接口关系

```text
GET  /api/interviews?pageNum=1&pageSize=10
GET  /api/interviews/{id}
POST /api/interviews/{id}/finish
GET  /api/interviews/{id}/report
```

报告生成不是“点击后马上一定有结果”。后端可能先返回生成中，前端需要轮询报告状态。

## 二、页面状态

```ts
const sessions = ref<InterviewSessionListVO[]>([])
const total = ref(0)
const pageNum = ref(1)
const pageSize = ref(10)
const loading = ref(false)

const drawerVisible = ref(false)
const detail = ref<InterviewSessionDetailVO | null>(null)
const detailLoading = ref(false)
const drawerReport = ref<InterviewReportVO | null>(null)
const reportLoading = ref(false)
const reportMessage = ref('')
let reportTimer: number | null = null
```

列表数据和抽屉详情不要复用同一个变量。列表只需要标题和状态，详情还包括消息；混在一起会导致关闭抽屉后旧详情残留。

## 三、分步实现

### Step 1：加载分页列表

```ts
async function refresh() {
  if (!auth.token) return
  loading.value = true
  try {
    const page = await listInterviews(pageNum.value, pageSize.value)
    sessions.value = page.records
    total.value = page.total
  } finally {
    loading.value = false
  }
}
```

登录态从无到有时，通过 watch 自动刷新：

```ts
watch(
  () => auth.token,
  (token) => {
    if (token) {
      pageNum.value = 1
      refresh()
    }
  },
)
```

这就是“页面可能已经挂载，但用户稍后才登录”的场景。只在 `onMounted` 请求一次是不够的。

### Step 2：打开详情前重置旧状态

```ts
async function openDetail(item: InterviewSessionListVO) {
  drawerVisible.value = true
  detail.value = null
  drawerReport.value = null
  detailLoading.value = true
  try {
    detail.value = await getInterviewDetail(item.id)
  } finally {
    detailLoading.value = false
  }
}
```

先清理旧数据，避免用户点击第二条记录时短暂看到第一条记录的对话或报告。

### Step 3：触发报告生成

```ts
async function loadReport(id: number) {
  reportLoading.value = true
  try {
    const status = await finishInterview(id)
    reportMessage.value = status.message || ''

    if (status.status === 1 && status.report) {
      drawerReport.value = status.report
      await refresh()
      return
    }

    startReportPolling(id)
  } finally {
    reportLoading.value = false
  }
}
```

这里要结合后端实际状态码核对含义，不要只凭变量名称猜。当前前端类型已经把报告状态限制为 `0 | 1 | 2`，应与后端 VO 和阶段文档保持一致。

### Step 4：轮询并停止

```ts
function startReportPolling(id: number) {
  stopReportPolling()
  reportTimer = window.setInterval(() => {
    void pollReport(id)
  }, 2000)
}

function stopReportPolling() {
  if (reportTimer !== null) {
    window.clearInterval(reportTimer)
    reportTimer = null
  }
}
```

`start` 前先 `stop`，可以避免重复启动多个 timer。轮询成功拿到报告、报告失败、抽屉关闭、页面卸载，都要停止。

### Step 5：组件卸载时清理

```ts
onUnmounted(() => {
  stopReportPolling()
})
```

定时器是浏览器资源，不会因为 Vue 页面消失就自动停止。忘记清理会导致离开页面后仍然请求接口，甚至在多个页面之间重复刷新。

## 四、前端异步状态的四个问题

每次写异步流程，都问自己：

1. 请求开始时哪个按钮或区域要 loading？
2. 请求成功后哪个状态要更新？
3. 请求失败后用户能否重试？
4. 页面离开后还有没有 timer、流、监听器在运行？

这四个问题比单纯“接口能不能调通”更接近真实前端开发。

## 五、自测清单

- 未登录时显示登录引导，不调用面试历史接口。
- 登录成功后自动加载第一页。
- 翻页时只更新列表，不影响当前抽屉的数据模型。
- 点击不同记录时不会短暂显示上一条报告。
- 报告生成中每两秒查询一次，拿到报告后自动停止。
- 关闭页面或离开路由后，timer 已清理。
- 已评价会话再次查看报告不会重复触发模型生成，符合后端幂等约定。

## 六、初学者课堂：轮询到底是什么

浏览器本身不会自动知道后端的报告什么时候生成完成。轮询就是前端隔一段时间主动问一次：

```text
POST finish       告诉后端开始/完成面试
  ↓
GET report        询问当前状态
  ↓ 2 秒
GET report        还在生成吗？
  ↓ 2 秒
GET report        已完成，拿报告
```

它和 SSE 的区别是：SSE 是后端主动持续推送；轮询是前端定时发起多个普通请求。当前报告接口采用轮询，前端需要自己管理 timer。

## 七、为什么不能只写 `setInterval` 不保存返回值

错误写法：

```ts
setInterval(() => pollReport(id), 2000)
```

因为你丢掉了 timer id，后面没有办法停止它。正确写法：

```ts
let reportTimer: number | null = null

reportTimer = window.setInterval(() => {
  void pollReport(id)
}, 2000)
```

浏览器中的 `window.setInterval` 返回一个数字 id，TypeScript 项目中明确写成 `number | null`，可以表达“当前有没有轮询”。

## 八、轮询的停止条件

轮询不是越久越好，至少有这些停止条件：

```text
报告成功        保存 report，停止
报告失败        显示错误，停止
用户关闭抽屉    停止
页面卸载        停止
达到最大次数    停止并提示稍后查看
```

当前代码需要确保 `pollReport` 在成功或失败时调用 `stopReportPolling()`。如果后端长时间不可用，还应增加最大轮询次数或截止时间，避免无限请求。

## 九、请求竞态和当前查看的记录

用户可能先打开记录 A，又快速打开记录 B。A 的详情请求晚返回时，不能覆盖 B 的抽屉。初版可以在打开新记录时先清空旧数据；更稳的做法是记录当前 id：

```ts
const activeSessionId = ref<number | null>(null)

async function openDetail(item: InterviewSessionListVO) {
  activeSessionId.value = item.id
  const detail = await getInterviewDetail(item.id)
  if (activeSessionId.value !== item.id) return
  // 只有仍然是当前记录，才写入页面
}
```

这和题库分页里的请求竞态是同一个问题：异步完成顺序不一定等于发起顺序。

## 十、幂等和前端按钮

后端对已评价的会话把 `finish` 设计为幂等操作：重复调用不会重复生成报告。前端仍然要用 `reportLoading` 禁用按钮，因为幂等不等于可以让用户连续发送无数请求。后端保证正确性，前端负责减少误操作和改善体验。

## 十一、练习任务

1. 给轮询加 `maxAttempts = 30`，超过后停止并提示“请稍后在历史记录查看”。
2. 给报告生成按钮增加 disabled/loading 状态。
3. 把报告状态码转换成页面文案，不在 template 里散落数字判断。
4. 测试打开 A、立刻打开 B 时，最终抽屉必须显示 B。
5. 在浏览器中关闭抽屉，确认 Network 不再继续请求报告接口。
