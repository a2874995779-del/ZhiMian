# 任务 7.1.11 · 前端自动化测试入门

> 后端自动化测试已经建立了最小闭环。本任务为前端准备测试思路，建议在前端业务功能完成后执行。当前 `frontend/package.json` 还没有 Vitest 脚本，所以本任务会先讲清测试设计，再由你决定何时安装依赖并落地。

## 一、为什么前端也需要测试

前端 bug 不只是一片空白，还可能是：

- 筛选条件改变了，但页码没有回到 1；
- token 失效后页面仍显示登录用户名；
- SSE 收到两段文字时，第二段覆盖了第一段；
- 报告生成完成后 timer 没有停止；
- 收藏按钮显示已收藏，但接口实际失败。

这些问题都可以通过自动化测试提前固定下来。测试不是为了证明页面永远没问题，而是把“重要行为”写成可重复执行的检查。

## 二、测试工具和职责

推荐组合：

| 工具 | 职责 |
|---|---|
| Vitest | 测试运行器、断言、mock、fake timer |
| Vue Test Utils | 挂载 Vue 组件、触发点击、读取 DOM |
| jsdom | 在 Node 中模拟基本浏览器环境 |
| MSW 或 Axios mock | 模拟后端响应 |

测试不应该默认连接真实 MySQL、Redis 或 AI 服务。真实服务属于集成测试，运行慢、环境依赖多，应该单独安排。

## 三、测试分层

```text
纯函数测试       数量最多，最快
API 层测试        验证 URL、方法和数据转换
组件测试          验证点击、loading、空状态、错误提示
端到端测试        少量验证完整浏览器流程
```

智面最适合先测：

1. SSE 帧解析函数。
2. 排行榜数据转换函数。
3. 路由登录守卫。
4. 题库分页和筛选触发行为。
5. 报告轮询停止行为。

## 四、先把复杂逻辑抽成纯函数

现在 SSE 解析逻辑和网络读取混在 `chatInterviewStream` 中。进阶时可以抽成：

```ts
export function parseSseFrame(rawFrame: string): ChatStreamEvent | null {
  const line = rawFrame.split('\n').find((item) => item.startsWith('data:'))
  if (!line) return null
  return JSON.parse(line.slice(5).trim()) as ChatStreamEvent
}
```

纯函数的特点是：同样输入永远得到同样输出，不依赖 DOM、网络、localStorage 或当前时间，所以测试很简单。

测试案例应该覆盖：

```text
正常 delta       返回 delta 事件
done             返回 messageId
error            返回错误消息
没有 data 行     返回 null
非法 JSON        抛出错误或按约定返回 null
```

## 五、测试一个 Vue 组件的思路

不要测试 CSS 像素和 Element Plus 内部实现，测试用户能观察到的行为：

```ts
const wrapper = mount(QuestionBank, {
  global: {
    stubs: ['QuestionCard', 'QuestionDetailDrawer', 'el-pagination'],
  },
})
```

常见步骤：

1. mock `fetchQuestionPage` 返回一页题目。
2. `await flushPromises()` 等待异步请求完成。
3. 断言页面出现题目标题。
4. 修改筛选状态或触发按钮。
5. 断言 API 被正确参数调用。

测试关注的是“页面状态变化是否正确”，不需要真的把后端跑起来。

## 六、如何 mock API

概念上把真实 API 替换成可控函数：

```ts
vi.mock('../api/question', () => ({
  fetchQuestionPage: vi.fn(),
  fetchQuestionDetail: vi.fn(),
}))
```

测试中再指定返回值：

```ts
vi.mocked(fetchQuestionPage).mockResolvedValue({
  records: [{
    id: 1,
    title: '线程池参数',
    categoryId: 2,
    categoryName: 'Java 并发',
    tags: ['线程池'],
    difficulty: 2,
    viewCount: 3,
  }],
  total: 1,
  pageNum: 1,
  pageSize: 12,
})
```

mock 的价值是让测试自己控制成功、空数组和失败，不受真实后端数据变化影响。

## 七、测试异步页面时要等什么

点击按钮后，请求和 DOM 更新都不是同步完成的：

```text
trigger click
  → 事件函数开始
  → await API
  → ref.value 更新
  → Vue 更新 DOM
```

所以测试要等待 Promise 和 Vue 更新完成，再断言结果。直接在 click 后立刻读取 DOM，可能读到旧页面。

## 八、测试 timer 和轮询

报告轮询适合 fake timer：

```ts
vi.useFakeTimers()
// 挂载组件，触发开始轮询
vi.advanceTimersByTime(2000)
// 断言 pollReport 被调用
```

测试完成后恢复真实时间：

```ts
vi.useRealTimers()
```

如果组件卸载后仍然调用 API，测试应当失败。这能帮助你发现没有在 `onUnmounted` 中清理 timer 的问题。

## 九、登录态测试重点

至少测试：

```text
登录成功       store 保存 token 和 user
退出登录       store 与 localStorage 都清空
401 响应       自动执行 logout
受保护路由     无 token 时重定向
```

不要只断言 localStorage，因为真正影响页面的是 Pinia 响应式状态；也不要只断言 store，因为刷新页面后依赖的是 localStorage。

## 十、测试命名方式

测试名称应该描述行为和结果：

```text
切换分类时应将页码重置为第一页
收到多个 delta 时应按顺序追加到同一个气泡
报告成功后应停止继续轮询
未登录访问面试页应跳转到题库并打开登录引导
```

不要写“测试 loadQuestions 函数”，那只描述实现名，没有描述用户行为和预期。

## 十一、落地步骤

1. 安装 Vitest、Vue Test Utils 和 jsdom。
2. 在 `package.json` 增加 `test`、`test:watch` 脚本。
3. 新建 `src/utils/__tests__`，先测试纯函数。
4. 把 SSE 解析逻辑抽成纯函数并补测试。
5. 再测试一个简单组件，不要同时测试整个应用。
6. 最后把 `npm run test` 加入项目质量门槛。

## 十二、自测清单

- 能解释为什么前端测试不应该默认连接真实 AI 服务。
- 能区分纯函数测试、组件测试和端到端测试。
- 能写出 SSE 解析的正常、空帧、错误 JSON 三类用例。
- 能解释为什么异步测试需要等待 Promise 和 DOM 更新。
- 能说明 fake timer 为什么适合测试报告轮询。
- 能说出登录测试必须同时验证 Pinia 和 localStorage。
