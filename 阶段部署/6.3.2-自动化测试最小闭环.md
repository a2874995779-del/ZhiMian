# 6.3.2 自动化测试最小闭环

> 目标:给智面补上第一批自动化测试，让用户鉴权、答题记录、排行榜、学习仪表盘这些核心链路有最低限度的回归保护。

本阶段先做 Service 单元测试，不启动 Spring 容器，不连接 MySQL/Redis。这样测试速度快，也不会依赖本机数据库、Redis、AI Key 是否可用。

## 一、涉及文件清单

| 类型 | 文件 | 说明 |
| --- | --- | --- |
| 新建 | `src/test/java/com/zhimian/service/impl/UserServiceImplTest.java` | 测用户注册、重复用户名、登录成功、密码错误 |
| 新建 | `src/test/java/com/zhimian/service/impl/AnswerServiceImplTest.java` | 测答题记录、排行榜、学习仪表盘聚合 |

## 二、测试覆盖范围

### 2.1 用户模块

覆盖点:

1. 注册时密码必须 BCrypt 加密，不能明文入库。
2. 注册未传昵称时，默认使用用户名做昵称。
3. 注册时默认角色是 `user`。
4. 用户名重复时抛出 `BusinessException(CONFLICT)`。
5. 登录成功时返回 JWT 和用户信息。
6. 登录密码错误时抛出 `BusinessException(NOT_LOGIN)`。

对应测试类:

```text
src/test/java/com/zhimian/service/impl/UserServiceImplTest.java
```

### 2.2 答题与排行榜模块

覆盖点:

1. 题目不存在时，提交答题记录会抛出 `NOT_FOUND`。
2. 答对题目时，写入 `answer_record`。
3. 答对题目时，同时更新总榜和今日榜 Redis ZSet。
4. 答错题目时，只写答题记录，不更新排行榜。
5. 排行榜能把 Redis 分数映射为用户昵称和答对数量。
6. 非法 `limit` 直接返回空列表，不访问 Redis。

对应测试类:

```text
src/test/java/com/zhimian/service/impl/AnswerServiceImplTest.java
```

### 2.3 学习仪表盘

覆盖点:

1. 今日答对数量来自 `answer_record`。
2. 累计通关数来自历史答对记录。
3. 本周增量等于本周答对数减上周答对数。
4. 连续学习天数按最近连续答对日期计算。
5. 本周趋势返回 7 天数据，空日期补 0。
6. 正确率按 `correct / total` 计算。

## 四、为什么先测 Service

当前项目还没有测试基础设施，如果一开始就做全量 Controller 集成测试，会立刻碰到数据库初始化、Redis、JWT 请求头、AI 配置等大量环境问题。

先从 Service 单元测试开始有几个好处:

1. 改动小，容易跑通。
2. 能保护核心业务规则。
3. 不依赖外部服务，适合频繁运行。
4. 后续可以自然扩展到 Controller 和 Mapper 测试。

## 五、后续测试规划

下一步建议按这个顺序补:

1. `JwtInterceptorTest`:覆盖 `@Public`、`@RequireAdmin`、过期 token、黑名单 token。
2. `QuestionServiceImplTest`:覆盖题目新增、修改、删除、分页查询、标签映射。
3. `InterviewServiceImplTest`:用 fake AI client 覆盖创建面试、SSE 异常、报告生成状态。
4. `@WebMvcTest` Controller 测试:覆盖统一返回体、参数校验、权限拦截。
5. Mapper SQL 测试:后续引入 Testcontainers 或本地专用测试库后再做。
6. 前端最低门槛:继续把 `npm run build` 作为类型检查和构建检查。

## 六、容易踩的坑

1. 单元测试不要直接连 Redis，否则本地 Redis 没开时测试就会失败。
2. JWT 测试密钥必须大于等于 32 字节，否则 JJWT 会拒绝签名。
3. `UserContext` 是 ThreadLocal，测试结束必须清理。
4. Redis ZSet 返回顺序会影响排行榜断言，测试里用 `LinkedHashSet` 固定顺序。
5. Dashboard 用 `LocalDate.now()`，测试断言要跟运行日期动态计算，不能写死日期。

## 七、面试可讲点

- 为什么先做单元测试:在项目还没有测试基础设施时，先保护业务规则，再逐步上集成测试。
- 为什么 mock Redis/MySQL:单元测试关注业务分支，不让外部服务影响稳定性。
- 为什么要测异常路径:真实线上问题经常出在题目不存在、密码错误、重复提交这些边界。
- 为什么 `UserContext` 要清理:ThreadLocal 在线程复用时可能造成用户身份串号。
