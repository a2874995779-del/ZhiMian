## 二、分步实现

### Step 1:实体类 `model/entity/User.java`

```java
package com.zhimian.model.entity;

import lombok.Data;

import java.time.LocalDateTime;

/**
 * 用户表实体,与 user 表字段一一对应
 * 只在 Service/Mapper 层流动,禁止直接返回给前端(含 password!)
 */
@Data
public class User {

    private Long id;
    private String username;
    private String password;
    private String nickname;
    private String avatar;
    private String role;
    private Integer status;
    private LocalDateTime createTime;
    private LocalDateTime updateTime;
    private Integer isDeleted;
}
```

【讲解】

- 时间类型用 `LocalDateTime` 而不是老的 `java.util.Date`:不可变、线程安全、API 清晰,MyBatis 3.5+ 原生支持。
- `status`/`isDeleted` 用 `Integer` 而不是 `int`:数据库字段可能为 NULL 时,基本类型接不住;统一用包装类型是实体类惯例。

### Step 2:请求 DTO `model/dto/UserRegisterDTO.java`

```java
package com.zhimian.model.dto;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;
import lombok.Data;

/**
 * 注册请求参数
 */
@Data
public class UserRegisterDTO {

    @NotBlank(message = "用户名不能为空")
    @Size(min = 4, max = 32, message = "用户名长度需在 4~32 之间")
    @Pattern(regexp = "^[a-zA-Z0-9_]+$", message = "用户名只能包含字母、数字、下划线")
    private String username;

    @NotBlank(message = "密码不能为空")
    @Size(min = 8, max = 32, message = "密码长度需在 8~32 之间")
    private String password;

    @Size(max = 32, message = "昵称最长 32 个字符")
    private String nickname;
}
```

【讲解】

- 为什么不直接用 `User` 实体接参数?——实体有 `role`、`status` 等字段,用实体接参会被恶意请求体直接注入(`{"role":"admin"}` 就提权了),这叫**过度绑定/Mass Assignment 漏洞**,面试可讲。
- `@NotBlank` vs `@NotNull` vs `@NotEmpty` 的区别自己查一下,review 时我会问。
- `nickname` 没加 `@NotBlank`:允许不填,Service 里给默认值。

### Step 3:Mapper 接口 `mapper/UserMapper.java`

```java
package com.zhimian.mapper;

import com.zhimian.model.entity.User;
import org.apache.ibatis.annotations.Mapper;

/**
 * user 表数据访问
 */
@Mapper
public interface UserMapper {

    /**
     * 插入用户,自增 id 会回填到 user.id
     */
    int insert(User user);
}
```

### Step 4:SQL `resources/mapper/UserMapper.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.zhimian.mapper.UserMapper">

    <!-- useGeneratedKeys:插入后把数据库生成的自增主键回填到入参对象的 id 属性 -->
    <insert id="insert" parameterType="com.zhimian.model.entity.User"
            useGeneratedKeys="true" keyProperty="id">
        INSERT INTO user (username, password, nickname, role)
        VALUES (#{username}, #{password}, #{nickname}, #{role})
    </insert>

</mapper>
```

【讲解】

- **namespace 必须是 Mapper 接口的全限定名**,`id` 必须和方法名一致——写错的报错是 `Invalid bound statement (not found)`,开发文档预告过的坑,如果你撞上了,恭喜,印象更深。
- 只插业务字段:`status`、`is_deleted`、`create_time`、`update_time` 全部靠建表时的 `DEFAULT` 值,SQL 越短越不容易错。
- 全部用 `#{}`(预编译占位符),永远不要在这种地方用 `${}`。

### Step 5:加密器 Bean `config/AppConfig.java`

```java
package com.zhimian.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;

/**
 * 通用 Bean 装配
 */
@Configuration
public class AppConfig {

    /**
     * BCrypt 加密器:默认强度 10(2^10 轮),加密一次约几十毫秒
     * 注册为单例 Bean,全项目共用一个实例
     */
    @Bean
    public BCryptPasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

【讲解】

- BCrypt「慢」是故意的:攻击者拿到库也难以暴力碰撞。强度每 +1,耗时翻倍。
- 盐是加密时随机生成的,直接编码在输出的 60 字符密文里(`$2a$10$盐22字符+哈希31字符`),所以**不需要 salt 字段**——面试必考,对着密文结构讲最有说服力。

### Step 6:Service 接口与实现

`service/UserService.java`:

```java
package com.zhimian.service;

import com.zhimian.model.dto.UserRegisterDTO;

public interface UserService {

    /**
     * 注册,返回新用户 id
     */
    long register(UserRegisterDTO dto);
}
```

`service/impl/UserServiceImpl.java`:

```java
package com.zhimian.service.impl;

import com.zhimian.common.ErrorCode;
import com.zhimian.exception.BusinessException;
import com.zhimian.mapper.UserMapper;
import com.zhimian.model.dto.UserRegisterDTO;
import com.zhimian.model.entity.User;
import com.zhimian.service.UserService;
import lombok.RequiredArgsConstructor;
import org.springframework.dao.DuplicateKeyException;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;

@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {

    private final UserMapper userMapper;
    private final BCryptPasswordEncoder passwordEncoder;

    @Override
    public long register(UserRegisterDTO dto) {
        User user = new User();
        user.setUsername(dto.getUsername());
        // 密码只存 BCrypt 密文,明文从这一行之后就不再出现
        user.setPassword(passwordEncoder.encode(dto.getPassword()));
        // 昵称不填则默认用用户名
        user.setNickname(StringUtils.hasText(dto.getNickname()) ? dto.getNickname() : dto.getUsername());
        user.setRole("user");

        try {
            userMapper.insert(user);
        } catch (DuplicateKeyException e) {
            // 并发注册同名用户时,靠 uk_username 唯一索引兜底,把数据库异常转译成业务语义
            throw new BusinessException(ErrorCode.CONFLICT, "用户名已存在");
        }
        return user.getId();
    }
}
```

【讲解】

- `@RequiredArgsConstructor` + `final` 字段 = **构造器注入**。比 `@Autowired` 字段注入好在:依赖不可变、便于单测、循环依赖会在启动时暴露。review 时我会问你这三点。
- **没有先 `SELECT` 判断重名**:先查后插在并发下有竞态窗口(两个请求同时查到"不存在"),唯一索引 + 捕获 `DuplicateKeyException` 才是可靠防线。如果想给用户更快的失败反馈,可以查询前置,但 catch 这道兜底**不能省**。
- `DuplicateKeyException` 是 Spring 对各数据库驱动异常的统一转译(DataAccessException 体系),这也是个小考点:MyBatis 抛的原始异常是谁转译的?(`MyBatisExceptionTranslator`)
- `role` 硬编码 `"user"`:注册接口永远不允许由请求决定角色。
- 这里**不需要 `@Transactional`**:单条 INSERT 自带原子性。乱加事务是 review 常见扣分点,写多表操作(任务 1.6)时才用。

### Step 7:Controller `controller/AuthController.java`

```java
package com.zhimian.controller;

import com.zhimian.common.Result;
import com.zhimian.model.dto.UserRegisterDTO;
import com.zhimian.service.UserService;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * 认证相关:注册/登录/登出
 */
@RestController
@RequestMapping("/api/auth")
@RequiredArgsConstructor
public class AuthController {

    private final UserService userService;

    @PostMapping("/register")
    public Result<Long> register(@Valid @RequestBody UserRegisterDTO dto) {
        return Result.success(userService.register(dto));
    }
}
```

【讲解】

- `@Valid` 触发 DTO 上的校验注解,不通过时抛 `MethodArgumentNotValidException`——它会被你骨架里的 `GlobalExceptionHandler` 接住,返回 40000。**Controller 里一行校验代码都不用写**,这就是全局异常处理的价值。
- Controller 总共一行逻辑——这是正确状态。如果你发现自己在 Controller 里写 if/else 业务判断,停下来想想是不是该挪进 Service。
