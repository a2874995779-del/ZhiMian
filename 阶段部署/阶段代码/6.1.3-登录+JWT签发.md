## 二、分步实现

### Step 1:JWT 配置属性类 `config/JwtProperties.java`

```java
package com.zhimian.config;

import lombok.Data;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.stereotype.Component;

/**
 * 绑定 application.yml 中 zhimian.jwt.* 配置项
 */
@Data
@Component
@ConfigurationProperties(prefix = "zhimian.jwt")
public class JwtProperties {

    /** 签名密钥,长度必须 >= 32 字节,配在 application-local.yml,不进 git */
    private String secret;

    /** token 有效期(小时) */
    private long expireHours;
}
```

【讲解】

- `@ConfigurationProperties` 比逐个写 `@Value("${zhimian.jwt.secret}")` 更适合"一组相关配置":属性名自动按驼峰/中划线映射(`expire-hours` → `expireHours`),而且类型安全,配置项写错名字在启动时就能发现(需要开 `spring-boot-configuration-processor`,没开也不影响运行,只是 IDE 没提示,先不用管)。
- 密钥从配置读而不是硬编码在代码里——硬编码密钥一旦代码泄露(哪怕是私有仓库被拖库),所有已签发的 token 都可以被伪造。

### Step 2:JWT 工具类 `util/JwtUtil.java`

```java
package com.zhimian.util;

import com.zhimian.config.JwtProperties;
import io.jsonwebtoken.Claims;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;

import javax.crypto.SecretKey;
import java.time.Instant;
import java.time.temporal.ChronoUnit;
import java.util.Date;
import java.util.UUID;

/**
 * JWT 生成与解析
 */
@Component
@RequiredArgsConstructor
public class JwtUtil {

    private final JwtProperties jwtProperties;

    /**
     * 签发 token
     * @param userId 用户 id,存入 subject(sub)
     * @param role   角色,存入自定义 claim,供拦截器做权限判断(任务 1.3)
     */
    public String generateToken(Long userId, String role) {
        SecretKey key = Keys.hmacShaKeyFor(jwtProperties.getSecret().getBytes());
        Instant now = Instant.now();
        Instant expireAt = now.plus(jwtProperties.getExpireHours(), ChronoUnit.HOURS);

        return Jwts.builder()
                .id(UUID.randomUUID().toString())   // jti:唯一标识,登出黑名单(任务 1.4)靠它
                .subject(String.valueOf(userId))
                .claim("role", role)
                .issuedAt(Date.from(now))
                .expiration(Date.from(expireAt))
                .signWith(key)
                .compact();
    }

    /**
     * 解析并验签。token 被篡改、过期、格式非法都会在这里抛出运行时异常
     * (SignatureException / ExpiredJwtException / MalformedJwtException 等)
     */
    public Claims parseToken(String token) {
        SecretKey key = Keys.hmacShaKeyFor(jwtProperties.getSecret().getBytes());
        return Jwts.parser()
                .verifyWith(key)
                .build()
                .parseSignedClaims(token)
                .getPayload();
    }
}
```

【讲解】

- 这是 jjwt **0.12.x** 的新版流式 API(你 `pom.xml` 里已经是 0.12.6),和网上很多 0.11.x 的教程(`Jwts.builder().setSubject()...` )写法不一样,如果查资料时发现方法名对不上,大概率是版本差异,别怀疑自己敲错了。
- `subject` 只放 `userId`,**没有放用户名或任何业务信息**——JWT 的 payload 只是 Base64 编码,不是加密,任何人拿到 token 都能解码出明文(可以去 jwt.io 粘贴自己生成的 token 验证这一点)。所以 payload 里**绝不能出现密码、手机号等敏感信息**,这是开发文档任务 1.2 明确点出的坑。
- `signWith(key)` 才是真正防篡改的机制:签名由密钥计算得出,拿不到密钥就伪造不出合法签名,拦截器验签失败即拒绝——**JWT 的安全性 100% 依赖密钥不泄露**。
- `id(UUID...)` 生成的 jti 现在还用不上,是为任务 1.4(登出黑名单)预留的,先埋进去,不用现在实现黑名单逻辑。

### Step 3:登录请求 DTO `model/dto/UserLoginDTO.java`

```java
package com.zhimian.model.dto;

import jakarta.validation.constraints.NotBlank;
import lombok.Data;

@Data
public class UserLoginDTO {

    @NotBlank(message = "用户名不能为空")
    private String username;

    @NotBlank(message = "密码不能为空")
    private String password;
}
```

【讲解】

- 注意提示语要和字段对应——上次注册 DTO 里三个字段的 `@NotBlank` 提示语都复制成了"用户名不能为空",这次敲的时候留意一下,别再犯同样的复制粘贴错误。
- 登录 DTO 不需要 `@Size`/`@Pattern`:格式校验在注册时做过了,登录只需要确认"两个字段都传了",具体对不对交给密码比对去回答,不需要在这里重复校验格式(格式错的用户名/密码,查库或比对自然会失败)。

### Step 5:Mapper 新增查询方法

`mapper/UserMapper.java`:

```java
package com.zhimian.mapper;

import com.zhimian.model.entity.User;
import org.apache.ibatis.annotations.Mapper;

@Mapper
public interface UserMapper {

    int insert(User user);

    /**
     * 按用户名查询,查不到返回 null

    User selectByUsername(String username);
}
```

`resources/mapper/UserMapper.xml`(**注意 namespace 已改成 Mapper 接口全限定名**):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.zhimian.mapper.UserMapper">

    <insert id="insert" parameterType="com.zhimian.model.entity.User"
            useGeneratedKeys="true" keyProperty="id">
        INSERT INTO user (username, password, nickname, role)
        VALUES (#{username}, #{password}, #{nickname}, #{role})
    </insert>

    <select id="selectByUsername" resultType="com.zhimian.model.entity.User">
        SELECT id, username, password, nickname, avatar, role, status, create_time, update_time, is_deleted
        FROM user
        WHERE username = #{username} AND is_deleted = 0
    </select>

</mapper>
```

【讲解】

- `SELECT *` 没有用,显式列出字段:一是可读性(一眼看出查了哪些列),二是表结构以后加字段时不会意外多查出来影响 `resultType` 自动映射,三是这也是不少团队的编码规范,养成习惯。
- `WHERE username = #{username} AND is_deleted = 0`——**忘记加 `is_deleted = 0` 是逻辑删除模式下最常见的 bug**:用户注销后本该查不到,少了这个条件,注销用户还能登录。开发文档 2.0 节第 3 条提过这条规矩,这里是它第一次真正派上用场。

`service/impl/UserServiceImpl.java` 新增部分:

```java
package com.zhimian.service.impl;

import com.zhimian.common.ErrorCode;
import com.zhimian.exception.BusinessException;
import com.zhimian.mapper.UserMapper;
import com.zhimian.model.dto.UserLoginDTO;
import com.zhimian.model.dto.UserRegisterDTO;
import com.zhimian.model.entity.User;
import com.zhimian.model.vo.LoginVO;
import com.zhimian.model.vo.UserVO;
import com.zhimian.service.UserService;
import com.zhimian.util.JwtUtil;
import lombok.RequiredArgsConstructor;
import org.springframework.beans.BeanUtils;
import org.springframework.dao.DuplicateKeyException;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;

@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {

    private final UserMapper userMapper;
    private final BCryptPasswordEncoder passwordEncoder;
    private final JwtUtil jwtUtil;

    @Override
    public long register(UserRegisterDTO dto) {
        User user = new User();
        user.setUsername(dto.getUsername());
        user.setPassword(passwordEncoder.encode(dto.getPassword()));
        user.setNickname(StringUtils.hasText(dto.getNickname()) ? dto.getNickname() : dto.getUsername());
        user.setRole("user");

        try {
            userMapper.insert(user);
        } catch (DuplicateKeyException e) {
            throw new BusinessException(ErrorCode.CONFLICT, "用户名已存在");
        }
        return user.getId();
    }

    @Override
    public LoginVO login(UserLoginDTO dto) {
        User user = userMapper.selectByUsername(dto.getUsername());

        // 用户不存在 或 密码错误,统一返回同一个错误码和文案,不区分是哪一种
        if (user == null || !passwordEncoder.matches(dto.getPassword(), user.getPassword())) {
            throw new BusinessException(ErrorCode.NOT_LOGIN, "用户名或密码错误");
        }

        String token = jwtUtil.generateToken(user.getId(), user.getRole());

        UserVO userVO = new UserVO();
        BeanUtils.copyProperties(user, userVO);

        LoginVO loginVO = new LoginVO();
        loginVO.setToken(token);
        loginVO.setUser(userVO);
        return loginVO;
    }
}
```

【讲解】

- **`user == null` 和密码不匹配,抛的是同一个异常、同一句文案**。如果分开写"用户不存在"/"密码错误"两句提示,攻击者靠这个差异就能枚举出库里哪些用户名真实存在(俗称用户名/账号枚举漏洞),这是开发文档任务 1.2 明确要求验收的一点。
- `passwordEncoder.matches(明文, 密文)`——注意参数顺序,第一个是用户输入的明文密码,第二个是库里查出来的 BCrypt 密文。`matches` 内部会从密文里取出盐,对明文重新加密后比对,不需要你手动处理盐。
- `BeanUtils.copyProperties(user, userVO)`:按字段名把 `User` 的同名属性拷到 `UserVO`,`UserVO` 没有 `password` 字段,所以密文根本不会被拷过去——这是比手动一个个 `set` 更省事的写法,但**只在字段名严格对应时才安全**,以后字段一多容易"拷漏了不易发现",现在两个类字段还少,先用它,以后遇到更复杂的映射场景再讨论 MapStruct 之类的工具。
- `JwtUtil` 通过构造器注入进来,和 `UserMapper`、`BCryptPasswordEncoder` 是同一种写法,保持一致。

### Step 7:Controller 新增 `/login`

`controller/AuthController.java`:

```java
package com.zhimian.controller;

import com.zhimian.common.Result;
import com.zhimian.model.dto.UserLoginDTO;
import com.zhimian.model.dto.UserRegisterDTO;
import com.zhimian.model.vo.LoginVO;
import com.zhimian.service.UserService;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/auth")
@RequiredArgsConstructor
public class AuthController {

    private final UserService userService;

    @PostMapping("/register")
    public Result<Long> register(@Valid @RequestBody UserRegisterDTO dto) {
        return Result.success(userService.register(dto));
    }

    @PostMapping("/login")
    public Result<LoginVO> login(@Valid @RequestBody UserLoginDTO dto) {
        return Result.success(userService.login(dto));
    }
}
```

【讲解】没什么新知识点,和 `register` 一样一行代理转发,保持 Controller 的"薄"。

## 三、自测清单

```bash
# 0. 先注册一个测试账号(确认 role 有值、能成功)
curl -s -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"logintest","password":"abc12345","nickname":"登录测试"}'

# 1. 正确账号密码登录 → 期望 code=0,data.token 是一串 xxx.yyy.zzz,data.user 里没有 password 字段
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"logintest","password":"abc12345"}'

# 2. 密码错误 → 期望 code=40100,message="用户名或密码错误"
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"logintest","password":"wrongpass"}'

# 3. 用户名不存在 → 期望 code=40100,message 与上面【一字不差】
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"nobody_here","password":"abc12345"}'
```

再做两项人工检查:

4. **payload 不泄露敏感信息**:把 token 用 `.` 分成三段,取第二段用 `base64 -d` 解码(或去 jwt.io 粘贴),确认里面只有 `jti`/`sub`/`role`/`iat`/`exp`,**没有** `username`、`password`、`nickname`。
5. **篡改验签**:把拿到的 token 最后随便改一个字符,记下来——这一步现在还没有受保护的接口可以直接测(拦截器是任务 1.3 才做),但你可以写一个一次性的 JUnit 小测试,直接 `new` 一个 `JwtProperties` 填入和配置文件一样的 secret,调用 `jwtUtil.parseToken(篡改后的token)`,断言它抛出异常。测完可以把这个测试删掉或留着,任务 1.3 时还会用类似方式验证。
