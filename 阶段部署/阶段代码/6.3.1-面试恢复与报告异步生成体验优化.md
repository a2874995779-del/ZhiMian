# 6.3.1 面试恢复与报告异步生成体验优化

> 目标:解决三个体验问题:
>
> 1. 创建面试和生成报告响应慢。
> 2. 用户误关页面后，无法继续未结束面试。
> 3. 面试记录中点击生成报告时，前端先报错，过一会儿报告又出现，状态衔接不流畅。

本次优化的核心思路是:把“慢的 AI 调用”和“用户点击后的即时反馈”拆开。用户点击后先进入稳定状态，AI 慢慢生成，前端轮询结果，不让用户直接承受同步接口超时。

## 二、数据库改造

### 2.1 新环境建表 SQL

把 `sql/init.sql` 里 `interview_report` 表改成下面这样:

```sql
CREATE TABLE `interview_report` (
  `id`            BIGINT   NOT NULL AUTO_INCREMENT,
  `session_id`    BIGINT   NOT NULL COMMENT '会话 id',
  `score`         INT      DEFAULT NULL COMMENT '总分 0-100，生成中允许为空',
  `content`       JSON     DEFAULT NULL COMMENT '结构化报告:亮点/薄弱点/总评，生成中允许为空',
  `status`        TINYINT  NOT NULL DEFAULT 0 COMMENT '0-生成中 1-成功 2-失败',
  `error_message` VARCHAR(255) DEFAULT NULL COMMENT '生成失败原因',
  `create_time`   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time`   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_session_id` (`session_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT '面试评价报告表';
```

### 2.2 已有数据库迁移 SQL

如果你的本地库已经建好了，执行这个迁移:

```sql
ALTER TABLE interview_report
  MODIFY COLUMN score INT DEFAULT NULL COMMENT '总分 0-100，生成中允许为空',
  MODIFY COLUMN content JSON DEFAULT NULL COMMENT '结构化报告:亮点/薄弱点/总评，生成中允许为空',
  ADD COLUMN status TINYINT NOT NULL DEFAULT 1 COMMENT '0-生成中 1-成功 2-失败' AFTER content,
  ADD COLUMN error_message VARCHAR(255) DEFAULT NULL COMMENT '生成失败原因' AFTER status,
  ADD COLUMN update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP AFTER create_time;
```

解释:

- 原来 `finishInterview` 必须等 AI 生成完才能插入 `interview_report`，因为 `score/content` 都是 `NOT NULL`。
- 现在先插入一条 `status=0` 的报告任务，前端看到“生成中”。
- AI 成功后更新 `score/content/status=1`。
- AI 失败后更新 `status=2/error_message`，前端展示“生成失败，可重试”。

### 3.4 修改 `InterviewReportMapper.xml`

文件: `src/main/resources/mapper/InterviewReportMapper.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.zhimian.mapper.InterviewReportMapper">
    <insert id="insert" keyProperty="id" useGeneratedKeys="true">
        INSERT INTO interview_report (session_id, score, content, status)
        VALUES (#{sessionId}, #{score}, #{content}, 1)
    </insert>

    <insert id="insertGenerating">
        INSERT INTO interview_report (session_id, status)
        VALUES (#{sessionId}, 0)
        ON DUPLICATE KEY UPDATE
            status = IF(status = 2, 0, status),
            error_message = NULL
    </insert>

    <select id="selectBySessionId" resultType="com.zhimian.model.entity.InterviewReport">
        SELECT id, session_id, score, content, status, error_message, create_time, update_time
        FROM interview_report
        WHERE session_id = #{sessionId}
    </select>

    <update id="markSuccess">
        UPDATE interview_report
        SET score = #{score},
            content = #{content},
            status = 1,
            error_message = NULL
        WHERE session_id = #{sessionId}
    </update>

    <update id="markFailed">
        UPDATE interview_report
        SET status = 2,
            error_message = #{errorMessage}
        WHERE session_id = #{sessionId}
    </update>
</mapper>
```

解释:

- `insertGenerating` 用 `ON DUPLICATE KEY UPDATE` 保证幂等。
- 如果已有成功报告，重复点击不会覆盖。
- 如果上一次失败，允许重新置为生成中。

## 五、线程池配置

### 5.1 修改 `AppConfig.java`

文件: `src/main/java/com/zhimian/config/AppConfig.java`

```java
package com.zhimian.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;

import java.util.concurrent.Executor;
import java.util.concurrent.LinkedBlockingQueue;
import java.util.concurrent.ThreadPoolExecutor;
import java.util.concurrent.TimeUnit;

@Configuration
public class AppConfig {
    @Bean
    public BCryptPasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean("reportExecutor")
    public Executor reportExecutor() {
        return new ThreadPoolExecutor(
                2,
                4,
                60,
                TimeUnit.SECONDS,
                new LinkedBlockingQueue<>(100),
                r -> {
                    Thread t = new Thread(r);
                    t.setName("report-generator-" + t.getId());
                    return t;
                },
                new ThreadPoolExecutor.CallerRunsPolicy()
        );
    }
}
```

解释:

- 报告生成是慢任务，不能卡住 HTTP 请求线程。
- 队列必须有界，避免 AI 服务慢时任务无限堆积。
- `CallerRunsPolicy` 可以在压力大时反压调用方。

### 7.2 创建面试快速返回

用下面的 `createInterview` 替换原方法。核心变化是:不再同步调用 AI 生成开场白，改为固定开场白，创建接口会明显变快。

```java
@Override
public InterviewSessionVO createInterview(CreateInterviewDTO dto) {
    InterviewDirection direction = InterviewDirection.fromCode(dto.getDirection());
    if (direction == null) {
        throw new BusinessException(ErrorCode.PARAMS_ERROR, "暂不支持该面试方向");
    }

    Long userId = UserContext.getUserId();
    long activeCount = interviewSessionMapper.countInProgress(userId);
    if (activeCount >= MAX_ACTIVE_SESSIONS) {
        throw new BusinessException(ErrorCode.TOO_MANY_REQUESTS, "面试中的会话达到上限，若想继续，请先结束之前的对话");
    }

    InterviewSession session = new InterviewSession();
    session.setUserId(userId);
    session.setDirection(direction.getCode());
    session.setTitle(direction.getLabel() + " · " + LocalDate.now());
    session.setStatus(0);
    interviewSessionMapper.insert(session);

    String systemPrompt = buildSystemPrompt(direction);
    String openingMessage = buildFastOpeningMessage(direction);

    InterviewMessage systemMsg = buildMessage(session.getId(), "system", systemPrompt);
    InterviewMessage assistantMsg = buildMessage(session.getId(), "assistant", openingMessage);
    interviewMessageMapper.insert(systemMsg);
    interviewMessageMapper.insert(assistantMsg);
    contextManager.append(session.getId(), systemMsg);
    contextManager.append(session.getId(), assistantMsg);

    InterviewSessionVO vo = new InterviewSessionVO();
    vo.setId(session.getId());
    vo.setDirection(direction.getCode());
    vo.setOpeningMessage(openingMessage);
    return vo;
}
```

新增辅助方法:

```java
private String buildFastOpeningMessage(InterviewDirection direction) {
    return "你好，我是本场 " + direction.getLabel()
            + " 方向的面试官。我们直接开始，先请你用自己的话回答: "
            + firstQuestion(direction);
}

private String firstQuestion(InterviewDirection direction) {
    return switch (direction.getCode()) {
        case "java_concurrency" -> "线程池的核心参数有哪些？为什么不推荐直接使用 Executors 创建线程池？";
        case "jvm" -> "你能从运行时数据区开始，整体讲一下 JVM 的内存模型吗？";
        case "mysql" -> "MySQL 的 B+ 树索引为什么适合范围查询？";
        case "redis" -> "Redis 常见的数据结构有哪些？你在项目里会怎么选择？";
        case "system_design" -> "如果让你设计一个高并发排行榜服务，你会怎么设计读写链路？";
        default -> "请介绍一个你最熟悉的技术点，并说明它在项目中的使用场景。";
    };
}
```

解释:

- 开场白不再依赖 AI，所以“开始面试”会从十几秒降到毫秒级到几百毫秒级。
- 第一轮后续追问仍走原来的 SSE `chat`，不会损失核心 AI 面试体验。

### 7.3 报告生成改为异步

用下面的 `finishInterview` 替换原方法:

```java
@Override
public InterviewReportStatusVO finishInterview(Long sessionId) {
    InterviewSession session = mustFindOwnSession(sessionId);

    if (session.getStatus() == 0) {
        interviewSessionMapper.endSession(sessionId);
    }

    InterviewReport existing = interviewReportMapper.selectBySessionId(sessionId);
    if (existing != null && Integer.valueOf(1).equals(existing.getStatus())) {
        interviewSessionMapper.markReportReady(sessionId);
        return buildReportStatus(existing);
    }

    String lockKey = LOCK_PREFIX + sessionId;
    Boolean locked = stringRedisTemplate.opsForValue()
            .setIfAbsent(lockKey, "1", LOCK_TTL_SECONDS, TimeUnit.SECONDS);
    if (!Boolean.TRUE.equals(locked)) {
        return buildGeneratingStatus("报告正在生成中，请稍候");
    }

    try {
        interviewReportMapper.insertGenerating(sessionId);
        CompletableFuture.runAsync(() -> generateReportJob(sessionId, lockKey), reportExecutor);
        return buildGeneratingStatus("报告正在生成中，请稍候");
    } catch (RuntimeException e) {
        stringRedisTemplate.delete(lockKey);
        throw e;
    }
}
```

新增 `getReportStatus`:

```java
@Override
public InterviewReportStatusVO getReportStatus(Long sessionId) {
    mustFindOwnSession(sessionId);

    InterviewReport report = interviewReportMapper.selectBySessionId(sessionId);
    if (report == null) {
        return buildGeneratingStatus("报告尚未开始生成");

```

新增后台任务:

```java
private void generateReportJob(Long sessionId, String lockKey) {
    try {
        InterviewReport report = interviewReportMapper.selectBySessionId(sessionId);
        if (report != null && Integer.valueOf(1).equals(report.getStatus())) {
            interviewSessionMapper.markReportReady(sessionId);
            return;
        }

        List<InterviewMessage> history = interviewMessageMapper.selectBySessionId(sessionId);
        InterviewReportResult result = generateReportWithRetry(buildTranscript(history));

        interviewReportMapper.markSuccess(
                sessionId,
                result.score(),
                serializeReportContent(result)
        );
        interviewSessionMapper.markReportReady(sessionId);
    } catch (Exception e) {
        log.error("异步生成评价报告失败: sessionId={}", sessionId, e);
        interviewReportMapper.markFailed(sessionId, "评价报告生成失败，请稍后重试");
    } finally {
        stringRedisTemplate.delete(lockKey);
    }
}
```

新增状态组装方法:

```java
private InterviewReportStatusVO buildGeneratingStatus(String message) {
    InterviewReportStatusVO vo = new InterviewReportStatusVO();
    vo.setStatus(0);
    vo.setMessage(message);
    return vo;
}

private InterviewReportStatusVO buildReportStatus(InterviewReport report) {
    InterviewReportStatusVO vo = new InterviewReportStatusVO();
    vo.setStatus(report.getStatus());

    if (Integer.valueOf(1).equals(report.getStatus())) {
        vo.setReport(toReportVO(report));
        vo.setMessage("报告已生成");
    } else if (Integer.valueOf(2).equals(report.getStatus())) {
        vo.setMessage(report.getErrorMessage() == null ? "报告生成失败，请重试" : report.getErrorMessage());
    } else {
        vo.setMessage("报告正在生成中，请稍候");
    }
    return vo;
}
```

解释:

- 用户点击“结束面试”后接口立即返回 `status=0`。
- 前端展示生成中，不再误报网络错误。
- 真正的 AI 生成在后台线程池中执行。
- 失败时前端展示“重新生成”，而不是让用户看到莫名其妙的报错。

### 7.4 修改 `toReportVO`

因为 `content` 生成中允许为空，所以 `toReportVO` 要防御空值:

```java
@SuppressWarnings("unchecked")
private InterviewReportVO toReportVO(InterviewReport report) {
    if (report == null || report.getContent() == null) {
        throw new BusinessException(ErrorCode.CONFLICT, "报告还未生成完成");
    }

    InterviewReportVO vo = new InterviewReportVO();
    vo.setScore(report.getScore());
    vo.setCreateTime(report.getCreateTime());
    try {
        Map<String, Object> content = objectMapper.readValue(report.getContent(), new TypeReference<>() {});
        vo.setHighlights((List<String>) content.get("highlights"));
        vo.setWeaknesses((List<String>) content.get("weaknesses"));
        vo.setSummary((String) content.get("summary"));
    } catch (JsonProcessingException e) {
        throw new RuntimeException(e);
    }
    return vo;
}
```

## 十四、自测清单

### 14.1 创建面试

1. 登录用户。
2. 进入模拟面试舱。
3. 选择任意方向。
4. 页面应快速进入聊天状态，不再长时间等待 AI 开场白。
5. 数据库 `interview_session` 有一条 `status=0` 记录。
6. 数据库 `interview_message` 有 system 和 assistant 开场消息。

### 14.2 恢复面试

1. 开始一场面试。
2. 提问一轮或不提问都可以。
3. 刷新页面或关闭页面。
4. 进入“面试记录”。
5. `进行中` 会话右侧应出现“继续面试”按钮。
6. 点击后跳转 `/interview?sessionId=xxx`，历史对话能恢复。

### 14.3 结束并生成报告

1. 至少回答一轮。
2. 点击“结束面试 · 生成评价”。
3. 页面立即进入“评价报告生成中”。
4. 前端不应弹出网络错误。
5. 后端生成成功后，页面自动显示报告。
6. 数据库 `interview_report.status=1`，`score/content` 有值。
7. 数据库 `interview_session.status=2`。

### 14.4 报告失败重试

1. 临时断开 AI Key 或改错模型配置。
2. 点击结束面试。
3. 报告任务应变为 `status=2`。
4. 前端展示失败提示，不应一直转圈。
5. 修复配置后重新点击生成，应重新置为 `status=0` 并再次生成。

## 十五、容易踩的坑

1. 异步线程里不要用 `UserContext.getUserId()`，因为 ThreadLocal 不会自动跨线程传递。
2. `interview_report.score/content` 必须允许为空，否则无法先插入“生成中”任务。
3. 查询历史报告不要再调用 `finishInterview` 当成读取接口，应使用 `GET /api/interviews/{id}/report`。
4. 前端轮询要在页面卸载时 `clearInterval`，否则会重复请求。
5. `finishInterview` 要幂等，用户重复点击不能生成多份报告。
6. Redis 锁释放必须放在后台任务 finally 中，否则失败时会卡住后续重试。

## 十六、面试可讲点

- 为什么慢操作要异步化:避免 HTTP 请求线程长时间阻塞，也避免前端超时导致“假失败”。
- 为什么要有任务状态:用户需要稳定反馈，不能用网络请求是否超时代表任务是否失败。
- 为什么要幂等:用户重复点击、刷新、重试都是正常行为，接口必须能承受。
- 为什么异步线程不读 ThreadLocal:用户上下文绑定在原 HTTP 线程，异步任务要显式传参。
- 为什么报告状态单独放在 `interview_report`:会话状态和报告任务状态是两个生命周期，拆开更清楚。
